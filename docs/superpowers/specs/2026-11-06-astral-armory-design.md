# ASTRAL ARMORY: Roblox VFX + Scripter demo

Date: 2026-11-06. Owner: Nguyễn Cao Nam Khánh. Status: approved in chat, awaiting written-spec review.

## 1. Purpose

A portfolio demo that goes with a job application to a studio making a power-grinding MMO-RPG on Roblox. The application is for VFX and Scripter (main) and Builder (support). The demo must show:

- VFX quality: magical weapon summons, light beams and aura in a Fate-like style (original designs, no names, characters or exact looks from Fate), plus ki/aura/transformation as listed in the job post.
- Scripter quality: server-authoritative combat, a progression system with a passive tree and support gems in the style of Path of Exile 2 (mechanics only, no copied tree layout, node names or art), data persistence, clean module boundaries, unit tests.
- Builder quality: one optimized arena that runs well on mobile.

Deliverables:

1. `AstralArmory.rbxl`, built with `rojo build`.
2. A public GitHub repo with all source, tests and docs.
3. A 60–90 second video reel. Khánh records it with OBS from `docs/reel-script.md`.

Out of scope: custom character models, keyframe animations, multiple maps, monetization, multiplayer balancing beyond basic correctness.

## 2. Toolchain

All tools are in `D:\Tools\bin` (on the user PATH): Rojo 7.7.1, Lune 0.11.1, StyLua 2.6.0, Selene 0.32.0, luau-lsp 1.70.1.

- Roblox Studio uses its built-in MCP server (Assistant → Manage MCP Servers → Enable Studio as MCP server). It is used for playtesting, screenshots and input simulation during integration.
- Python 3 + Pillow generate procedural textures.
- ChatGPT (in the user's Chrome) generates 2–3 hero textures. Claude drives the browser. Agents never do this step.
- Blender is not used in v1. Weapons are built from parts in code.

```
  assets/
    Arena.rbxm         generated by tools/build_map.luau, mapped into Workspace.Arena
    textures/          generated PNGs (uploaded manually, ids go into Config/AssetIds)
  tools/

    gen_textures.py    Pillow script that writes assets/textures/*.png
  tests/
    run.luau           tiny test harness: lune run tests/run

  docs/
```

Rules:

- `src/shared/Logic` and `src/shared/Config` must not touch `game`, `Instance`, `Vector3`, `task`, `workspace` or any Roblox API. They take and return plain tables and numbers. This keeps them testable with Lune.
- Every other module may use the Roblox API.
- Module return values are typed with Luau type annotations. `--!strict` goes at the top of every file.

## 4. Gameplay

### 4.1 Base stats

| Stat | Value |
|---|---|
| maxHp | 100 + 10 per level above 1 |
| maxEnergy | 100 |
| energyRegen | 8 per second |
| moveSpeed | 18 |
| critChance | 0.05 |
| critMul | 1.5 |

### 4.2 Skills (`Config/Skills.luau`)

Every skill has `id`, `key`, `displayName` (Vietnamese), `tags`, `cost`, `cooldown`, and its own numbers.

| id | Key | Name | Tags | Cost | Cooldown | Numbers |
|---|---|---|---|---|---|---|
| `basic` | M1 | Chém | Melee | 0 | 0.35 | damage 12, range 8, 3-hit combo, third hit ×1.6 |
| `blade_rain` | Q | Mưa Kiếm Tinh Tú | Projectile, AoE, Summon | 30 | 6 | 18 per blade, count 12, radius 14, cast range 60 |
| `dawnbreaker` | E | Cột Sáng Bình Minh | Channel, Line | 40 | 8 | channel 1.2 s, damage 90, length 40, width 8 |
| `crimson_lance` | R | Giáo Huyết | Projectile, Pierce | 25 | 5 | damage 60, speed 120, range 80, pierces all, ignores armor |
| `hex_aegis` | F | Khiên Lục Giác | Defense, Duration | 35 | 14 | duration 3, absorbs 80 × shieldMul |
| `ascension` | T | Thăng Hoa | Buff, Transform | 50 | 45 | unlocks at level 10, duration 20, +30% damage, +50% energy regen, skills use the radiant variant |

An attack skill is any skill with damage. Gem sockets: `blade_rain`, `dawnbreaker`, `crimson_lance` and `hex_aegis` have 2 each. `basic` and `ascension` have none.

### 4.3 Support gems (`Config/Gems.luau`)

| id | Name | Fits | Effect |
|---|---|---|---|
| `multishot` | Đa Phát | Projectile | `blade_rain` +4 blades. `crimson_lance` +2 lances in a 20° spread. Damage ×0.85. |
| `frost` | Băng | attack skills, group `element` | element frost, hits slow 30% for 2 s |
| `flame` | Hoả | attack skills, group `element` | element flame, hits burn for 20% of hit damage over 3 s |
| `storm` | Lôi | attack skills, group `element` | element storm, hits chain to 2 nearby enemies for 50% |
| `wide_burst` | Nổ Lan | AoE or Projectile | radius ×1.4 and a 6-stud impact explosion for 30% damage |
| `swift_cast` | Tốc Thi | any socketed skill | cooldown ×0.75 |

A skill can hold at most one gem from the `element` group. The same gem id cannot go in both sockets of one skill. Gems are inventory items with instance ids. A gem in a socket leaves the inventory list until it is removed.

### 4.4 Progression (`Config/Progression.luau`, `Logic/Progression.luau`)

- Level 1 to 20. `xpToNext(L) = floor(100 * L^1.5)`.
- Gaining XP can cross several levels at once. XP above max level is discarded.
- 1 passive point per level gained. Level 20 gives 19 points total.

### 4.5 Passive tree (`Config/Passives.luau`, `Logic/PassiveTree.luau`)

- 40 nodes: 1 start node plus 13 per region, each region having 9 small, 3 notable and 1 keystone.
- Regions: `might` (Uy Lực, red: damage, max HP), `swift` (Tốc Biến, green: cooldown, move speed, crit), `insight` (Thấu Suốt, blue: energy, energy regen, AoE size, shield).
- Each node has `id`, `region`, `kind` (`start` | `small` | `notable` | `keystone`), `name` (Vietnamese), `mods` (list of `{stat, op = "add" | "mul", value}`), `x`, `y` (UI coordinates, start at 0,0, radius about 600) and `links` (node ids, undirected).
- Value guide: a small node is about +4% damage, +12 max HP, −3% cooldown, +2% crit, +10 max energy or +5% AoE. A notable is about 3 small nodes.
- Keystones change rules and are read through `stats.keystones`:
  - `blood_oath` (Huyết Thệ): skill costs come out of HP instead of Energy, +40% damage.
  - `endless_arsenal` (Kho Kiếm Vô Tận): `blade_rain` +6 blades, each blade ×0.75 damage.
  - `radiant_mind` (Tâm Quang): `ascension` lasts until Energy reaches 0 and drains 6 Energy per second instead of having a fixed duration.
- A node can be allocated only if it is linked to an allocated node and the player has a free point. The start node is always allocated and costs nothing.
- Respec is free in the demo and refunds all points.

### 4.6 Enemies and boss (`Config/Enemies.luau`)

- `hollow_knight` (Hiệp Sĩ Rỗng): an R15 rig made at runtime with `Players:CreateHumanoidModelFromDescription`. Dark colors and two neon eye parts.
  - At level L: hp `60*(1+0.25*(L-1))`, damage `8*(1+0.2*(L-1))`, XP `floor(20*L^1.2)`.
  - Speed 14, attack range 5, attack cooldown 1.2 s.
  - Respawns 8 s after death. 10 alive at a time.
  - Inner ring spawns levels 1–3, outer ring levels 4–8.
  - 12% chance to drop a random gem.
- `eclipse_warden` (Hộ Vệ Nhật Thực): the same rig scaled ×3.
  - Level 12, hp 4000, XP 2000, always drops 2 gems.
  - Summoned at the altar by a player at level 8 or higher. The altar cools down 60 s after the boss dies.
  - Phase 1: every 5 s, slam at the target's position. A 1.2 s red telegraph circle shows first. Radius 16, damage 35.
  - Phase 2, below 50% HP: also summons 8 shadow blades at random spots near players, each with a 1 s telegraph and 25 damage in radius 5. Move speed +25%. An enrage aura turns on.

### 4.7 Arena (`tools/build_map.luau` → `assets/Arena.rbxm`)

- A floating ruin over a sunset sky: a circular stone platform about 220 studs across, broken pillars, a glowing rune circle in the center, inner and outer spawn rings marked by subtle floor runes, a boss altar on a raised dais at the north edge, and a player spawn at the south edge.
- Lighting lives in `default.project.json` (Lighting properties plus Atmosphere, Bloom, ColorCorrection, SunRays and Sky children). Future lighting technology.
- Performance budget: under 2,000 BaseParts in the arena. Large surfaces use few big parts. Decorative parts are Anchored with `CanCollide`, `CanTouch` and `CanQuery` false. `Workspace.StreamingEnabled = true`.
- Invisible boundary walls keep players and enemies on the platform. Falling below Y = −50 respawns the player.

### 4.8 UI and input (`src/client/UI`, `src/client/Input`)

- HUD: HP and Energy bars, XP bar with level number, skill hotbar (Q E R F T) with cooldown sweeps and locked state for `ascension` below level 10, and floating damage numbers colored by element (crits larger).
- P opens the passive tree. It shows nodes at their `x, y` with links as lines, supports pan and zoom, a click allocates a node, hover shows a tooltip, and it has a free-points counter and a Reset button.
- G opens the gem screen: an inventory grid and the 2 sockets for each skill. Click a gem, then a socket, to equip. Invalid sockets are dimmed with the reason shown.
- Mobile: ContextActionService touch buttons for M1 and each skill, plus buttons to open P and G. UI scales with UIScale based on screen size.
- Aim: the mouse hit position on PC, the camera center on touch.
- All strings are Vietnamese, kept in one `Config/Strings.luau`, so English can be added later.

## 5. Architecture and contracts

### 5.1 Authority

The server owns all state: level, XP, points, allocation, gems, sockets, HP, Energy, cooldowns and the transformed flag. The client sends intents. The server validates them, applies them, and broadcasts effects. The client only renders VFX and UI.

### 5.2 Remotes (`src/shared/Net.luau`)

`Net.luau` exports the remote names and creates them on the server under `ReplicatedStorage.Remotes` (`Net.server()`). Clients wait for them (`Net.client()`).

| Name | Kind | Direction | Payload |
|---|---|---|---|
| `CastSkill` | RemoteEvent | C→S | `skillId: string, target: Vector3` |
| `AllocatePassive` | RemoteEvent | C→S | `nodeId: string` |
| `ResetPassives` | RemoteEvent | C→S | none |
| `SocketGem` | RemoteEvent | C→S | `skillId: string, slot: number, gemInstanceId: string?` (nil unsockets) |
| `SummonBoss` | RemoteEvent | C→S | none |
| `StateSync` | RemoteEvent | S→owner | `PlayerState` (5.3), sent on every change, coalesced to at most 10 per second |
| `SkillFx` | RemoteEvent | S→all | `FxEvent` (5.4) |
| `DamagePopup` | RemoteEvent | S→all | `{position: Vector3, amount: number, crit: boolean, element: Element}` |
| `BossFx` | RemoteEvent | S→all | `{event: "telegraph" \| "slam" \| "blades" \| "enrage" \| "defeated", position: Vector3?, radius: number?, delay: number?}` |

Server validation for `CastSkill`: the skill exists and is unlocked, it is off cooldown, the player can pay the cost (Energy, or HP under `blood_oath`), the player is alive, and casts are limited to 20 per second per player. `target` is clamped to the skill's range from the character's root.

### 5.3 `PlayerState`

```lua
type Element = "none" | "frost" | "flame" | "storm"
type GemInstance = { id: string, gemId: string }
type PlayerState = {
  level: number, xp: number, xpToNext: number, points: number,
  allocated: { [string]: true },
  gems: { GemInstance },                                  -- unsocketed inventory
  sockets: { [string]: { [number]: GemInstance? } },      -- skillId -> slot -> gem
  hp: number, maxHp: number, energy: number, maxEnergy: number,
  cooldowns: { [string]: number },                        -- skillId -> server os.clock() when ready
  transformed: boolean, transformEndsAt: number?,
  serverClock: number,                                    -- os.clock() at send time, for cooldown UI
}
```

### 5.4 `FxEvent` and `SkillSpec`

`Logic/SkillResolver.luau` is the only place that turns config + sockets + stats into final numbers. The server uses the result to deal damage, and the same result's visual fields go to clients.

```lua
type SkillSpec = {
  skillId: string, damage: number, cooldown: number, cost: number,
  costResource: "energy" | "hp",
  count: number, radius: number, range: number, length: number?, width: number?,
  speed: number?, duration: number?, absorb: number?,
  element: Element, pierce: boolean, impactExplosion: boolean,
  spreadDeg: number?, radiant: boolean,
}
SkillResolver.resolve(skillId: string, socketedGemIds: { string }, stats: Stats, transformed: boolean): SkillSpec

type FxEvent = {
  skillId: string, casterUserId: number,
  origin: Vector3, target: Vector3,
  spec: SkillSpec,           -- the visual fields drive VFX variants
  seed: number,              -- shared random seed so all clients see the same blade layout
  serverTime: number,        -- workspace:GetServerTimeNow() at cast
}
```

### 5.5 `Stats`

```lua
type Stats = {
  damageMul: number, maxHp: number, maxEnergy: number, energyRegen: number,
  cooldownMul: number, moveSpeed: number, critChance: number, critMul: number,
  aoeMul: number, shieldMul: number, keystones: { [string]: true },
}
Stats.compute(level: number, allocated: { [string]: true }, buffs: { transformed: boolean }): Stats
```

Mods with `add` are summed per stat first. Then mods with `mul` multiply: `(base + sum(add)) * prod(1 + mul)`.

### 5.6 Logic module APIs (pure, tested)

- `Progression.xpToNext(level): number`, `Progression.addXp(level, xp, amount): (newLevel, newXp, levelsGained)`
- `PassiveTree.canAllocate(allocated, nodeId, points): (boolean, reason?)`, `PassiveTree.allocate(...)`, `PassiveTree.reset(allocated): (allocatedStartOnly, refunded)`, `PassiveTree.validateGraph(nodes): (boolean, errors)` (links symmetric, every node reachable from start, exactly 40 nodes, 1 keystone per region)
- `GemRules.canSocket(skillId, slot, gemId, currentSockets): (boolean, reason?)`
- `Stats.compute(...)` (5.5)
- `SkillResolver.resolve(...)` (5.4)
- `Damage.roll(base, stats, rng): (amount, crit)`, where `rng` is a function returning a value in [0, 1) so tests are deterministic.

### 5.7 Server services (`src/server`)

`Main.server.luau` boots the services in order: PlayerData, Combat, Enemies, Boss.

- `PlayerDataService`: loads and saves through DataStore `AstralArmory_v1`, keyed by userId. It saves level, xp, allocated, gems and sockets on leave and every 60 s. Every DataStore call is in `pcall`. If DataStore is unavailable (offline `.rbxl`, API access off), the session runs without saving and a warning is printed once.
- `CombatService`: handles the remotes, validation, cooldowns, Energy regen, `hex_aegis` absorb, `ascension`, hit detection (spatial queries with `OverlapParams` and raycasts for the lance), damage application, burn, slow and chain, and the `DamagePopup` and `SkillFx` broadcasts.
- `EnemyService`: spawns and respawns hollow knights by ring, runs a simple chase-and-attack AI on a 0.2 s heartbeat (no per-enemy loops), grants XP to everyone who hit the enemy within 10 s, and rolls gem drops.
- `BossService`: altar `ProximityPrompt` plus the `SummonBoss` remote, the phase machine, telegraphs through `BossFx`, and rewards.

### 5.8 Client (`src/client`)

- `Main.client.luau` boots `Net.client()`, the input, UI and VFX controllers.
- `Vfx/`: one module per skill (`BladeRain`, `Dawnbreaker`, `CrimsonLance`, `HexAegis`, `Ascension`, `BasicSlash`), plus `BossTelegraph`, `Impact`, `Common` (pooling, Debris cleanup, camera shake, screen flash) and `ElementTint`. Each module exports `play(event: FxEvent)`. Element and radiant variants come only from `spec` and `VfxPalette`.
- VFX rules:
  - Every effect cleans itself up within its duration + 1 s.
  - Blade and lance parts come from a pool.
  - No more than 40 ParticleEmitters alive per effect.
  - Camera shake and flash only for the local caster, or within 30 studs.
  - Effects must look right with the built-in fallback textures when `Config/AssetIds` has no custom id yet.
- `Models/` (shared): `SwordModel.build()` and `LanceModel.build()` create part-built weapons with Neon edges and Attachments for trails. The server welds a sword to each character's RightHand on spawn.

### 5.9 Textures

- `tools/gen_textures.py` writes these 512×512 PNGs with alpha:
  - `glow_soft`, `glow_star`, `spark`, `smoke_soft`, `ring_runes`, `hex_cell`, `slash_arc`, `beam_core`
  - `explosion_flipbook_4x4`, a 2048 px sheet
- Khánh uploads them through the Asset Manager. The ids go into `Config/AssetIds.luau`. Until then, `AssetIds` falls back to built-in Roblox textures.
- After v1, Claude generates 2–3 hero textures with ChatGPT in the browser: the rune circle, the blade glint and the aura flame.

## 6. Testing and verification

- Unit tests (Lune, `lune run tests/run`) cover every Logic module:
  - XP curve values and multi-level gains
  - passive graph validation
  - allocation connectivity, points and respec
  - each keystone's effect on Stats and SkillSpec
  - gem tag fit, element exclusivity and duplicate rejection
  - resolver results, for example `blade_rain` + `multishot` → count 16 and `blade_rain` + `multishot` + `endless_arsenal` → count 22
  - deterministic damage rolls
- Static checks: `stylua --check src tests tools`, `selene src`, and `rojo build -o AstralArmory.rbxl` must all pass.
- Studio playtest checklist (built-in MCP plus screenshots):
  - spawn with a sword
  - each of the 6 skills plays its VFX and deals damage
  - kill enemies until level 10 (debug command `/lvl n` in Studio only)
  - allocate passives and see the stats change
  - socket `frost` on `blade_rain` and see the blades turn blue
  - summon the boss, see both phases, win
  - Device Emulator on a phone: touch buttons work and FPS is stable
- Done means every unit test passes, every static check passes, the playtest checklist is completed with screenshots saved in `docs/screenshots/`, and the code review has no blocking findings.

## 7. Build plan (multi-agent)

Five parallel agents, each owning disjoint files:

| Agent | Owns |
|---|---|
| Progression | `Config/Skills`, `Config/Gems`, `Config/Passives`, `Config/Progression`, `Config/Strings`, all of `Logic/`, `tests/` |
| Combat | `Net.luau`, `Config/Enemies`, all of `src/server/` |
| VFX | `VfxPalette`, `Config/AssetIds`, `Models/`, `src/client/Vfx/`, `tools/gen_textures.py`, `assets/textures/` |
| Builder | `tools/build_map.luau`, `assets/Arena.rbxm`, the Lighting section of `default.project.json` |
| UI | `src/client/UI/`, `src/client/Input/`, `src/client/Main.client.luau` |

The contracts in section 5 are fixed before the agents start. An agent that needs something outside its files codes against the contract, and stubs it locally in a test only if needed.

After the agents: an integration pass runs the static checks and unit tests and fixes seams. Then Claude playtests in Studio over MCP. Then one review agent, then fixes. The GitHub push and the reel script come last.

## 8. Risks

- Built-in Studio MCP not enabled yet: the playtest phase waits on Khánh enabling it. Everything before that runs headless.
- Asset upload needs Khánh's Roblox account: fallback textures keep the demo working.
- Lune version differences in `roblox` library APIs: Builder agent verifies `build_map.luau` against Lune 0.11.1 docs.
- R15 runtime rigs without animation: enemies use the default R15 walk and slash animation ids, set in `Config/Enemies`. If the animations fail to load, the enemies still move and fight.
